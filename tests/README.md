# Проверки Image Format Lab

Команды выполняются из корня проекта. Сборщик и тесты используют Node.js;
браузерные сценарии — Playwright и Chromium. Для независимого чтения файлов
нужны Python, Pillow и pillow-heif. Версии зависимостей и установка в CI описаны
в [docs/CI.md](../docs/CI.md).

## Запуск

```cmd
npm ci --prefix scripts
npm --prefix scripts run build
npm --prefix scripts test
```

Полный набор запускает отдельный Chromium и создаёт временные файлы.
Наборы `build-version` и `release-workflow` также создают временные Git-репозитории
для проверки тегов и выпуска. Исходный репозиторий и удалённые репозитории
эти сценарии не изменяют.

Набор `release-publishing` проверяет событие выпуска, фильтр `v*`, принадлежность
тега main с подставленными ответами Git, состав файлов и загрузку вложений
через имитацию API. Он не запускает Git, браузер или сетевые запросы.

Корневой HTML не хранится в Git. После получения исходников и перед тестами
выполняйте `npm --prefix scripts run build`. Checks и Release собирают HTML
автоматически до тестирования. Набор `publication-policy` проверяет запрет
отслеживания готового HTML и порядок сборки в обоих workflow без запуска Git.

Отдельные наборы можно перечислить после `--`:

```cmd
npm --prefix scripts test -- analysis-layout analysis-visibility analysis-viewport
npm --prefix scripts run test:build
npm --prefix scripts run test:sources
npm --prefix scripts run test:codecs
```

Последние три команды проверяют сборку, исходные комплекты и сжатие кодеков
без запуска браузера. Полный перечень наборов находится в [run.cjs](run.cjs).
Ненулевой код завершения означает ошибку хотя бы одного набора.

## Что проверяют наборы

| Группа | Предмет проверки |
| --- | --- |
| Сборка и выпуск | Воспроизводимость HTML, импорты, встроенные данные, версии, теги main, состав выпуска |
| Исходные комплекты | SHA-256, соответствие ZIP явным исходникам, лицензии и замена кодека |
| Алгоритмы | GIF/BMP, JPEG/TIFF, точный TIFF16 с проверкой младших битов, кодирование JPEG с проверкой маркеров и обратным чтением, метрики, гистограммы, вычисленные сигналы BT.709, Waveform/Parade и профиль линии по целым RGBA8/16, смешанная разрядность в наложении и разнице, точный путь через Worker, вектороскоп |
| Состояние и компоновка | Настройки, тема, размеры панелей, область анализа, наложение, импорт файлов |
| Браузерный интерфейс | Сравнение, масштаб, пакет и предпросмотр, отмена, устаревшие операции, экспорт |
| Форматы | HEIC/AVIF, JPEG XL, WebP lossless, TIFF и ICO; чтение результатов независимыми декодерами |
| Автономный HTML | Обычный выпуск в отдельной папке с отключённой сетью и настоящими скачиваниями |

Набор `png-indexed` проверяет индексы 1/2/4/8 бит, блоки PLTE/tRNS,
обратное чтение независимым UPNG, идентичность палитры собственному GIF
при одинаковых настройках и неизменность исходных пикселей.

Часть проверок интерфейса работает с моделью DOM в Node.js. Такие проверки
проверяют состояние и вызовы, но не подтверждают геометрию и реальные жесты браузера.

Набор `pixel-buffer` проверяет описание RGBA-буферов, точные копии uint8/uint16/float32,
расчёт объёма и отклонение некорректных размеров/типов. Модель ImageData/Canvas
проверяет адаптер RGBA8, описание исходника и результата, уменьшение/ICO и освобождение
данных сравнения. Он не проверяет браузерную растеризацию или управление цветом.
Запуск без браузера: `npm --prefix scripts test -- pixel-buffer`.

Набор `pixel-metrics` проверяет PSNR/alpha для 8/10/12/16-битных целых и float32:
младшие разряды, эквивалентные шкалы, явный floatPeak, прозрачность, крайние float32,
совместимость размеров/цветовых меток и некорректные отсчёты. Прежние RGBA8-результаты
сверяются без допуска округления. Настоящий Worker-поток Node запускает собранный
`compute.worker.mjs` через сервис приложения: проверяются порог по байтам, передача
описателей/параметров, очередь, ошибки и повтор, сохранность исходных массивов и путь
без Worker. Модель предпросмотра проверяет передачу описателей и освобождение bitmap
при ошибке метрик. Запуск: `npm --prefix scripts test -- pixel-metrics`.

Набор `histogram-precision` проверяет все 65 536 целых уровней, младшие разряды,
прежние RGBA8-частоты, alpha/подложки/области, float32-интервалы и выходы за диапазон.
Проверяются совместимость шкал, сохранение суммы при группировке, точная разница,
настоящий собранный Worker в потоке Node и сохранность исходных массивов.
PNG/JSON проверяются для целых, float и разных разрядностей в трёх видах:
отчёт использует собственный размер, JSON сохраняет исходные счётчики.
Запуск без браузера: `npm --prefix scripts test -- histogram-precision`.
Проверки `analysis-visibility` и `analysis-overlay` также проверяют передачу
описателя, кеш параметров float, первое раскрытие и несовместимые цветовые метки.

Набор `error-histogram` без браузера проверяет точные нулевые совпадения,
перестановку пикселей, младший бит RGBA16, нормировку 8/16 бит, прозрачность,
подложку, область и несовместимые данные. Собранный Worker сверяется с ядром;
PNG и JSON проверяются для отдельного графика и наложения. Браузерный
`viewer-error-histogram` проверяет обновление готовых ячеек, отсутствие кодирования
от переключателей и очистку старого графика при пересчёте.

Набор `error-profile` проверяет абсолютную ошибку каждого пикселя линии до
группировки, её среднее и пики, подложку и прозрачность, область, обратную линию,
младший бит RGBA16, несовместимые размеры/цветовые пространства и точные счётчики
значений на границах целочисленной гистограммы. Запуск без браузера:
`npm --prefix scripts test -- error-profile`.

Набор `ssim` проверяет собственный одномасштабный расчёт по прямой контрольной
формуле 11×11, отражение края, совпадение и симметрию, подложку и прозрачность,
точность RGBA16, область и отказы для несопоставимых растров. Запуск без браузера:
`npm --prefix scripts test -- ssim`.

Набор `pixel-inspector` проверяет точные отсчёты и младшие биты, RGB при alpha=0,
знаковые разницы в нативной и общей шкале, несовместимые данные, диапазоны и
сохранность буферов. Проверяются координаты при DPR/масштабе/смещении, границы
изображения и центрирование. Настоящие контроллеры инспектора, просмотра и
ячеек работают на модели DOM: ввод, жесты и отмена, ожидание/ошибка/смена файла,
2/4 ячейки и отсутствие кодирования от выбора точки.
Запуск без браузера: `npm --prefix scripts test -- pixel-inspector`.

Браузерный `viewer-pixel-inspector` открывает PNG16 без сети, проверяет реальную
таблицу, мышь и клавиатуру, RGBA8/16, инвалидирование результата, DPR 2 и узкое
окно. При включённых артефактах сохраняет снимок узкого интерфейса.

Набор `file-passport` без браузера проверяет JPEG/PNG из независимо собранных
контейнерных образцов: глубины/палитру/alpha, progressive, коэффициенты компонентов,
неоднозначную цветовую схему, несколько сканов, byte stuffing и поздние метаданные.
Проверяет обрезанные/ошибочные структуры, CRC IHDR, ограничения чтения, отмену,
bpp и объём рабочего буфера. Виртуальный PNG с большим IDAT проверяет пропуск
сжатых данных без большого выделения памяти. JPEG-образцы проверяют структуру,
их тестовые энтропийные данные не предназначены для декодирования изображения.
При заданном `IMAGE_TEST_PYTHON` дополнительно проверяются настоящие JPEG/PNG,
сохранённые Pillow: baseline/progressive, 4:4:4/4:2:2/4:2:0, RGB/RGBA/палитра/16 бит.
Настоящие контроллеры на модели DOM проверяют исходный и выходной Blob, кнопку,
кеш, ожидание/ошибку, отмену и отбрасывание устаревших ответов.

Браузерный `viewer-file-passport` использует PNG16 и настоящий браузерный JPEG:
проверяет сведения файлов, отсутствие перекодирования от открытия окна,
обновление при пересчёте, Escape/фокус и узкую компоновку. При включённых
артефактах сохраняет снимок окна. Запуск без браузера: `npm --prefix scripts test -- file-passport`.

Набор `analysis-report` проверяет отрисовку PNG из рассчитанных данных на модели
Canvas: размеры отчёта независимо от панели и DPR, общую шкалу, выбранную область
и сохранность размеров графиков интерфейса. Браузер для него не требуется.

`reference-samples` проверяет определения шести образцов, неизменные пиксели трёх
контрольных PNG, точное чтение/запись TIFF16-образца и PNG16 с ICC.
`viewer-files` проверяет выбор из меню и открытие точных TIFF16 и PNG16 с ICC
в автономном HTML. `experiment-protocol`
проверяет SHA-256 входа и результатов,
настройки, защиту от устаревшего состояния и ограничения размера без браузера.
`viewer-experiment-protocol` проверяет создание образца, сценарий и скачивание
протокола в автономном интерфейсе; при включённых артефактах сохраняет снимок.

`quality-series` без браузера проверяет бюджет, выбор лучшей измеренной точки,
недоминируемые точки, последовательность проб, ошибку, отмену и признаки
полного/частичного JSON-протокола. `quality-series-controller` проверяет десять
проб, таблицу/график, SHA-256 при экспорте, пересчёт бюджета без кодирования,
сохранность настроек ячеек и остановку во время кодирования на модели DOM.
Браузерный `viewer-quality-series` в CI проверяет автономный запуск на
контрольном образце, JSON-протокол, таблицу и график, пересчёт бюджета,
сохранность настроек ячеек и остановку.

`wipe-view` проверяет сопоставимость готовой пары, подтверждённые размеры блоков
и ограничение числа линий сетки. `heif-blocks` сверяет AVIF с известными
суперблоками, реальные HEIC-образцы и отказ от сетки при преобразовании
 координат или повреждённых данных.
`jxl-blocks` кодирует и декодирует настоящие файлы встроенным libjxl и проверяет
передачу карты из Worker: области VarDCT должны покрывать растр, а Modular не
получает DCT-сетку.
`modern-options` проверяет значения по умолчанию, сохранение настроек и передачу
параметров Worker. `modern-native-options` сравнивает реальные WebP/JPEG XL-файлы
при разных усилиях кодирования и проверяет обратное чтение без потерь.
`jpeg-jxl-reconstruction` проверяет побайтовое восстановление обычного и
прогрессивного JPEG с метаданными, отказ для JXL без данных восстановления и
передачу исходных сжатых байтов через Worker без RGBA.
`jpeg2000` проверяет реальный OpenJPEG: JP2/J2K, обратимое кодирование 8/16 бит,
RGBA и ICC, кодирование с потерями, повреждённый ввод и обмен с Worker.
Дополнительно проверяются выбор формата, запись режима в отчёт и передача точного
16-битного растра при сохранении.
`icc-sdr` проверяет матричные RGB ICC-профили, преобразование точного uint16
в SDR sRGB без изменения исходных кодов, чтение/запись PNG iCCP и выбор
исходного либо преобразованного растра при сохранении PNG16, JP2 и J2K.
`icc-extended` проверяет выбор точного чтения для PNG8 с ICC, сохранение исходных
отсчётов и профиля в PNG8/16 и TIFF16, приоритет iCCP над сопутствующими
gAMA/cHRM и явный отказ повреждённых либо неподдержанных TIFF16 с ICC.
`color-sdr` проверяет координаты CIE xy и Lab по SDR sRGB, опубликованные пары
CIEDE2000, область, прозрачность и подложку, согласованность 8/16-битных
значений, ограничение выборки, отказ при неподдержанном цветовом пространстве,
преобразование точного исходника по матричному ICC до ограничения sRGB и долю
отсчётов вне sRGB. Проверяются переход D50 → D65, соответствие области при
разных размерах и совпадение расчёта в Worker с ядром без потери буферов.
`tiff-icc-worker` без браузера проверяет передачу исходных 16-битных значений
и ICC между TIFF Worker и вызывающим потоком при записи и чтении.
`avif-speed` проверяет сохранение скорости, отчёт и передачу через Worker;
`avif-native-speed` сравнивает реальные AVIF-файлы, обратное чтение и сохранение HEIC ABI.
`viewer-wipe-view` в CI проверяет автономное совмещение, выбор режима до загрузки файла, управление границей с
клавиатуры, появление сетки при увеличении и возврат к четырём окнам; при
включённых артефактах сохраняет снимок.
`analysis-guides` сверяет границы и концы линии на просмотре с фактическими
целочисленными координатами анализа.
`crop-source` проверяет создание независимого растра из точной области,
сохранение всех RGBA8/16-отсчётов в новом PNG и точное повторное чтение PNG8.

Браузерные сценарии с доступом к внутренним операциям используют временную
сборку с [support/browser-entry.mjs](support/browser-entry.mjs). Этот адаптер
не входит в пользовательский HTML. Набор [standalone-release.cjs](standalone-release.cjs)
отдельно открывает обычный корневой HTML через интерфейс; инструментированная
сборка не заменяет эту проверку.

## Окружение и результаты

| Переменная | Назначение |
| --- | --- |
| `NODE_PATH` | Каталог модулей с установленным Playwright |
| `IMAGE_TEST_PYTHON` | Исполняемый файл Python; по умолчанию `python` |
| `IMAGE_TEST_BROWSER` | Необязательный путь к Chromium |
| `IMAGE_TEST_HEIC_NATIVE=1` | Независимое декодирование HEIC через pillow-heif |
| `IMAGE_TEST_LOGS` | Каталог журналов отдельных наборов |
| `IMAGE_TEST_SCREENSHOTS` | Каталог снимков браузерных сценариев |
| `IMAGE_TEST_RUN_ID` | Префикс файлов результатов: латинские буквы, цифры, дефис и подчёркивание |

Для локальных результатов используйте выделенный каталог `local/test-results/`,
который исключён из публикации. Остальные пользовательские каталоги `local/`
недоступны тестовым помощникам. В CI используется временный `test-results/`.
Журналы и снимки не входят в исходники или материалы выпуска.

```cmd
set IMAGE_TEST_LOGS=local/test-results
set IMAGE_TEST_SCREENSHOTS=local/test-results
set IMAGE_TEST_RUN_ID=manual
npm --prefix scripts test
```

## Тестовые изображения

Наборы создают синтетические изображения в памяти либо читают файлы из
`tests/fixtures/`. Манифесты описывают параметры и ожидаемые данные.
Для JPEG/GPano применяется собственный синтетический образец; пользовательские
фотографии не нужны. TIFF-образцы формируются скриптом
[support/generate-tiff-fixtures.py](support/generate-tiff-fixtures.py), HEIC —
[support/generate-heic-fixtures.py](support/generate-heic-fixtures.py).
Условия тестовых материалов указаны в [ASSETS.md](../ASSETS.md).

`raster-codecs.cjs` проверяет собственную запись BMP8 с палитрой и RLE8,
её заголовки, длинные серии, заливку прозрачности и обратное чтение встроенным
BMP-декодером. Также проверяются встроенные BMP/TIFF WASM без браузера на
собственных синтетических данных: палитры/RLE/маски, точная прозрачность,
сжатие TIFF, BigTIFF, порядок байтов, раздельные каналы, 16-bit и ориентацию,
а также прежние JPEG-in-TIFF примеры. `raster-settings.cjs` проверяет
настройки сравнения, профили и независимый черновик пакета.
`raster-worker.cjs` запускает настоящий Worker-поток Node с кодом обработчика
приложения и проверяет обмен буферами, ошибки и резервное чтение JPEG-in-TIFF.

Набор `png-precision` проверяет независимые PNG-образцы через Node zlib:
серые/RGB/RGBA, 8/16 бит, все фильтры, Adam7, tRNS, разбиение IDAT;
сохранение всех 65536 уровней, скрытого RGB и alpha, понижение 16→8,
расширение 8→16, точные метрики/гистограмму и настоящий Worker Node.
UPNG независимо читает сохранённые 16-битные байты без вызова toRGBA8.
Проверяются повреждённые блоки/CRC, ограничение распаковки и памяти,
цветовые описания, пути decode/encode, исходный файл и запрет уменьшения PNG16.
`raster-settings` также проверяет PNG-разрядность в профилях, настройках,
независимых ячейках и черновике пакета. Браузерные геометрия и цветовой вывод
не проверяются моделями. Запуск: `npm --prefix scripts test -- png-precision raster-settings`.

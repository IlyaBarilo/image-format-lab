# Image Format Lab — проверки и выпуск через GitHub Actions

## Проверки изменений

[Checks](../.github/workflows/ci.yml) запускается автоматически при push.
Сервер GitHub использует Ubuntu 24.04, Node.js 24.16.0 и Python 3.13.
Зависимости сборки устанавливаются командой `npm ci --prefix scripts` по
`scripts/package-lock.json` в `scripts/node_modules/`. Сначала проверяются
пути отслеживаемых файлов и актуальность уже закоммиченного корневого HTML;
устаревший файл приводит к ошибке, а не незаметно заменяется новой сборкой.

Затем выполняется полный `npm --prefix scripts test`, включая
браузерный `standalone-release`. Он открывает отдельную копию обычного HTML
с отключённой сетью и записывает хеш проверенных байтов. HEIC дополнительно
декодируется независимым pillow-heif. Опциональная нативная проверка JPEG XL
через pillow-jxl этим workflow не включается; встроенные проверки форматов
остаются частью полного набора.

Журналы сохраняются в артефакт Actions на 14 дней, в том числе при ошибке
тестов. Для пользовательского скачивания предназначены файлы **Releases**.
Chromium запускается только на сервере GitHub при запуске workflow.

## Выпуск через Releases

Автор открывает **Releases → Draft a new release**, создаёт тег с префиксом
`v` из `main`, вводит заголовок и описание и нажимает **Publish release**.
Поддерживаются `v1`, `v0.1`, `v0.1.0`, `v0.1.2.3` и полные SemVer-теги,
например `v1.2.3-rc.1`. [Порядок публикации](PUBLISHING.md).

[Release](../.github/workflows/release.yml) автоматически запускается по событию
`release: published`. Задание сборки выбирает только теги с префиксом `v`
(маска `v*`); для остальных тегов задания пропускаются.
Числовой формат проверяется отдельно, поэтому `v-anything` не становится
допустимым номером. `workflow_dispatch` для обычной работы не используется.
Сохранение черновика и редактирование описания не запускают новую сборку.

В настройках репозитория **Enable release immutability должна быть выключена**:
эта схема прикрепляет вложения к уже опубликованному выпуску. Неизменяемый
опубликованный выпуск отклоняется до установки тестовых зависимостей;
перед загрузкой файлов его состояние проверяется ещё раз через API.

Checkout получает **коммит события публикации** и полную историю. Проверка
требует совпадения этого коммита с тегом и его вхождения в историю `main`.
Тег, перенесённый после события, не подменяет исходники. Затем проверяются
отслеживаемые входы и актуальность обычного HTML, собирается версия с точным
номером и адресами исходников `releases/download/<tag>/<имя ZIP>`.
Рабочий scripts/source-release.json не изменяется и может оставаться с `null`.

После полного тестирования сборка повторяется в режиме `--check`. Упаковщик
требует успешный браузерный отчёт с теми же SHA-256 и размером HTML, без
внешних запросов и ошибок страницы. В `dist/release/` попадают только:

| Файл | Назначение |
| --- | --- |
| `image-format-lab.html` | Готовое автономное приложение |
| `gifenc-1.0.3-sources.zip` | Соответствующие исходники gifenc и лицензии |
| `heic-sources.zip` | Исходники HEIC/AVIF, лицензии и средства пересборки |
| `SHA256SUMS.txt` | Контрольные суммы трёх файлов выше |

Файлы передаются отдельному заданию по ID артефакта текущего запуска. Оно
проверяет состав, хеши и ссылки, затем получает существующий релиз по ID
из события GitHub. ID, тег и опубликованное состояние должны совпадать;
удалённый тег должен указывать на протестированный коммит.
Зависимости npm в задании загрузки не устанавливаются.

Перед первой загрузкой проверяются все уже существующие одноимённые вложения.
Совпадающие по размеру и SHA-256 файлы повторно не загружаются; конфликт
останавливает процесс. Посторонние вложения автора остаются нетронутыми.
Перед каждой новой загрузкой повторно проверяются релиз и коммит тега.
Каждый загруженный файл скачивается через API для проверки байтов.
Исходные ZIP загружаются перед HTML, чтобы ссылки на них уже были доступны
при появлении приложения среди вложений.

Все четыре вложения также проверяются скачиванием **без токена**, с повторами
при задержке доступности. Если GitHub считает этот выпуск Latest, проверяется
[постоянная ссылка на HTML](https://github.com/IlyaBarilo/image-format-lab/releases/latest/download/image-format-lab.html).
Автоматизация сохраняет заголовок, описание, предварительный статус и выбор
Latest автора; она не создаёт новый релиз и не публикует черновик.
Суффикс `_latest` для имени файла не создаётся.

## Если процесс завершился ошибкой

Релиз виден сразу после Publish release, а файлы приложения появляются после
сборки и проверок. При ошибке релиз и уже загруженные вложения остаются
доступными; до завершения Release ссылку на приложение распространять не следует.

Повторный запуск допускает точное совпадение уже загруженных файлов и добавляет
только недостающие. Несовпадающие файлы, изменившийся тег, чужой ID выпуска,
черновик и неизменяемый выпуск приводят к остановке. Вложения не перезаписываются,
релизы и теги не удаляются. Если байты исходников изменились, используйте новый
номер версии. Сбой публичного скачивания не отменяет состоявшуюся загрузку.

## Права и инструменты

Checks и сборка выпуска имеют `contents: read`. Право `contents: write`
получает только задание публикации; встроенный GITHUB_TOKEN передаётся
только шагу отправки. Checkout не сохраняет учётные данные Git. Проверки
запускаются по push; файлы выпуска собираются после Publish release. Параллельные
публикации сериализованы. Отслеживаемые пути проверяются через `git ls-files`:
запрещённые local/, AGENTS.md, .gitignore и личные материалы отклоняются до
чтения их содержимого. Неотслеживаемые файлы в сбор релизных вложений не входят.

GitHub Actions закреплены полными SHA: checkout 7.0.1, setup-node 7.0.0,
setup-python 7.0.0, upload-artifact 7.0.1, download-artifact 8.0.1.
Общая установка описана в [setup-tests](../.github/actions/setup-tests/action.yml):
Playwright 1.63.0 ставится отдельно от зависимостей приложения во временный
каталог runner; [Python-зависимости](../scripts/ci-requirements.txt) —
Pillow 12.3.0 и pillow-heif 1.7.0. Служебные инструменты сохраняют свои условия:
[Actions](https://github.com/actions/checkout/blob/v7.0.1/LICENSE),
[Playwright](https://github.com/microsoft/playwright/blob/v1.63.0/LICENSE),
[Pillow](https://pypi.org/project/pillow/12.3.0/),
[pillow-heif](https://pypi.org/project/pillow-heif/1.7.0/).
Они не копируются в HTML или четыре релизных вложения. 

Конфигурация опирается на официальные инструкции
[синтаксиса Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax),
[Playwright в CI](https://playwright.dev/docs/ci),
[Releases API](https://docs.github.com/en/rest/releases/releases) и
[Release assets API](https://docs.github.com/en/rest/releases/assets).

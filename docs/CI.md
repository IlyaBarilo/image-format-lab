# Image Format Lab — проверки и выпуск через GitHub Actions

## Проверки изменений

[Checks](../.github/workflows/ci.yml) запускается автоматически при push.
Четыре задачи выполняются параллельно в независимых рабочих копиях на Ubuntu 24.04,
с Node.js 24.16.0 и Python 3.13. Каждая проверяет отслеживаемые входы, собирает
обычный корневой HTML и запускает свою группу из [единого реестра](../tests/suites.cjs).

| Группа | Состав |
| --- | --- |
| core | Node, сборка, численные алгоритмы, настройки и проверки тестовой инфраструктуры |
| viewer | Файлы, пакетная конвертация и основные сценарии интерфейса |
| analysis | Графики, области, профиль, экспорт и инспекторы |
| codecs | Браузерные кодеки, обычный автономный HTML и диагностика Chromium/Firefox |

Все зарегистрированные наборы входят ровно в одну группу; пропуск или дублирование
вызывает ошибку реестра. Дополнительный запуск диагностики Firefox имеет отдельное
имя в отчёте. Ошибка одной группы не отменяет остальные. Итоговое задание **test**
успешно только при успехе всех четырёх групп.

Установка использует прежние закреплённые версии и lock-файл. Кешируются загрузки
npm и pip; ключи учитывают соответствующие файлы зависимостей, платформу и версии
инструментов. Установка и проверки целостности продолжают выполняться после
восстановления кеша. Группа core не устанавливает Playwright и браузеры. Две
группы интерфейса получают Chromium, группа codecs — Chromium и Firefox.

Runner один раз собирает инструментированный HTML на браузерную группу.
Дочерние процессы переиспользуют тот же файл с проверкой SHA-256; они не удаляют
его, очистку выполняет владелец после группы. Отдельный `standalone-release`
продолжает открывать копию **обычного** HTML с отключённой сетью и сохранять
хеш проверенных байтов. HEIC дополнительно читается независимым pillow-heif.
Нативная проверка JPEG XL через pillow-jxl в workflow не включена.

Для каждого набора видны START и результат PASS/FAIL/TIMEOUT, время, код выхода
и сигнал завершения. Вывод дочерних процессов передаётся сразу и сохраняется
целиком. Ошибка не скрывается внутренними строками PASS. Лимит одного Node-набора —
5 минут, браузерного — 10 минут; превышение завершает дерево процессов с ошибкой.
В конце выводятся самые долгие наборы, а полная сводка остаётся в JSON и Summary
задания. Общая длительность включает подготовку общего HTML.

После тестов, включая неуспешные, `build -- --check` проверяет актуальность HTML,
а проверка репозитория подтверждает неизменность отслеживаемых исходников.
Корневой HTML среди отслеживаемых файлов считается ошибкой.

Отдельные артефакты `checks-<group>-<run>-<attempt>` хранят журналы и JSON-сводку
14 дней, в том числе при ошибке. Для скачивания приложения используются Releases.
Параллельные задачи сокращают последовательное ожидание; суммарные минуты runner
могут отличаться. Фактическое время видно после выполнения Checks на GitHub.
Chromium и Firefox запускаются на сервере GitHub.

## Проверки релизной сборки

[Release](../.github/workflows/release.yml) проверяет, что тег указывает на
коммит события публикации и этот коммит входит в историю `main`. Сборщик
включает в HTML точное имя тега и ссылки на исходные ZIP той же версии.

После полного набора тестов сборщик сверяет HTML в режиме `--check`.
Упаковщик сопоставляет его размер и SHA-256 с браузерным отчётом об автономной
работе. В выпуск входят четыре файла.

| Файл | Назначение |
| --- | --- |
| `image-format-lab.html` | Готовое автономное приложение |
| `gifenc-1.0.3-sources.zip` | Соответствующие исходники gifenc и лицензии |
| `heic-sources.zip` | Исходники HEIC/AVIF, лицензии и средства пересборки |
| `SHA256SUMS.txt` | Контрольные суммы трёх файлов выше |

Проверка скачивает вложения по публичным ссылкам и сравнивает их с проверенными
байтами. Для выпуска **Latest** она также проверяет
[постоянную ссылку на HTML](https://github.com/IlyaBarilo/image-format-lab/releases/latest/download/image-format-lab.html).

## Инструменты проверок

GitHub Actions закреплены полными SHA: checkout 7.0.1, setup-node 7.0.0,
setup-python 7.0.0, upload-artifact 7.0.1, download-artifact 8.0.1.
Общая установка описана в [setup-tests](../.github/actions/setup-tests/action.yml):
Playwright 1.63.0 ставится отдельно от зависимостей приложения во временный
каталог runner; [Python-зависимости](../scripts/ci-requirements.txt) —
Pillow 12.3.0 и pillow-heif 1.7.0. Служебные инструменты сохраняют свои условия:
[Actions](https://github.com/actions/checkout/blob/v7.0.1/LICENSE),
[Playwright](https://github.com/microsoft/playwright/blob/v1.63.0/LICENSE),
[Pillow](https://pypi.org/project/pillow/12.3.0/),
[pillow-heif](https://pypi.org/project/pillow-heif/1.7.0/).
Они не копируются в HTML или четыре релизных вложения.

Конфигурация опирается на официальные инструкции
[синтаксиса Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax),
[Playwright в CI](https://playwright.dev/docs/ci),
[Releases API](https://docs.github.com/en/rest/releases/releases) и
[Release assets API](https://docs.github.com/en/rest/releases/assets).

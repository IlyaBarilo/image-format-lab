# Image Format Lab — для разработчика

Устройство исходников, сборка и проверки приложения.
Общее описание возможностей — в [README](../README.md), карта модулей —
в [src/README.md](../src/README.md).

## Сборка

Нужны Node.js 18+ и npm; CI использует Node.js 24.16.0.
Команды выполняются из корня проекта:

```sh
npm ci --prefix scripts
npm --prefix scripts run build
npm --prefix scripts run build -- --check
```

Манифесты npm и зависимости сборки находятся в `scripts/`.
Первичная установка требует доступа к npm. После установки сборка использует
локальные исходники и закреплённые библиотеки из `vendor/`.
Результат — **`image-format-lab.html` в корне**. Это самостоятельное приложение:
стили, JavaScript, Worker, кодеки и уведомления встроены в HTML.
Версия в интерфейсе локальной сборки не показывается.
Готовый HTML не хранится в Git: после получения исходников сначала выполните
сборку. Перед тестированием пересобирайте его после правок исходников.
Проверка `build -- --check` сравнивает существующий локальный HTML с результатом
сборки и не создаёт отсутствующий файл.

Чтобы результат не попадал в список новых файлов Git, добавьте правило
`/image-format-lab.html` в локальный `.gitignore` или `.git/info/exclude`.
Игнорирование не снимает ранее добавленный файл с отслеживания.

Для автоматической пересборки при изменении исходников:

```sh
npm --prefix scripts run dev
```

## Работа с исходниками

- Правки приложения вносите в `src/`, затем пересобирайте HTML.
  Ручные изменения выходного файла заменяются сборкой.
- Чистые алгоритмы размещаются в `src/core/` и получают исходник изображения
  явно. Сервисы и компоненты связываются в `src/application.mjs`.
- Настройки сравнения и пакета независимы. После смены параметров или файла
  устаревший результат не должен отображаться или скачиваться.
  Освобождайте bitmap, Blob URL и больше не нужные буферы.
- Вычислительный Worker использует общие модули алгоритмов.
  Тестовый адаптер не должен попадать в обычный выпуск.

## Проверки

Быстрая проверка сборки без браузера:

```sh
npm --prefix scripts run test:build
```

Остальные наборы выбираются по изменению. Для экспорта проверяйте реальные
байты результата независимым декодером, а не только его предпросмотр.
Полный `npm --prefix scripts test` запускает в том числе Chromium и требует
окружения Playwright и Python с Pillow. Команды установки, отдельные наборы
и ограничения проверок описаны в [tests/README.md](../tests/README.md).

[GitHub Actions](CI.md) собирает HTML из исходников и запускает полный набор
тестов после push. Готовый файл не требуется в checkout. Инструкции
для выпуска — в [PUBLISHING.md](PUBLISHING.md).

## Библиотеки и материалы

Версии сторонних компонентов меняются вместе с исходниками, лицензиями,
манифестом SHA-256 и проверками. `node scripts/build-vendor.cjs` пересоздаёт
обёртку и манифест из локальных файлов; происхождение и условия новой зависимости
нужно оценивать отдельно.

Собственный код — [MIT](../LICENSE). Сохраняйте авторство и уведомления
стороннего кода: его условия перечислены в [NOTICE.md](../NOTICE.md).
Изображения и оформление описаны в [ASSETS.md](../ASSETS.md).
Исходные ZIP кодеков публикуются рядом с HTML по [инструкции выпуска](PUBLISHING.md).

### Сопровождение лицензионных документов

README содержит короткие ссылки на MIT, NOTICE и ASSETS. Подробные условия,
обязательные уведомления и доступ к исходникам описываются в NOTICE.md;
инструкции сборки находятся в документации разработчика.
Сокращение README не отменяет предоставление текстов и исходников из поставки.

Единый реестр компонентов — [vendor/components.json](../vendor/components.json).
Окно «Лицензии» получает этот реестр при сборке; вторую таблицу версий и условий
в README или NOTICE вручную не поддерживаем. Полные тексты лицензий остаются
отдельными неизменёнными файлами, на которые ссылается реестр.

После изменения реестра обновите его запись в манифесте и пересоберите HTML:

```sh
node scripts/build-vendor.cjs
npm --prefix scripts run build
npm --prefix scripts run build -- --check
```

Сборщик vendor использует явный перечень локальных файлов. Он также пересобирает
gifenc. Сохраняйте полные лицензионные тексты и проверяйте, что правка документации
не меняет исполняемую логику кодеков. При изменении документов внутри исходного
комплекта пересоберите соответствующий ZIP, затем манифест и HTML.
Изменение NOTICE.md тоже требует пересборки HTML: документ встроен в
`embedded-notices`. Тексты из реестра включены в `embedded-codecs`.
Проверки сборки контролируют наличие уведомлений и совпадение встроенного
реестра с исходным JSON.

### Пересборка библиотек

| Компоненты | Исходники и инструкция |
| --- | --- |
| gifenc / PnnQuant | [Читаемые модули и сборщик](../vendor/sources/gifenc-1.0.3/README.md) |
| TIFF-часть UTIF | [Адаптированные исходники и описание изменений](../vendor/sources/utif/README.md) |
| JPEG | [Закреплённые исходники libjpeg-turbo и WASM-сборщик](../vendor/sources/jpeg/README.md) |
| HEIC / AVIF | [Исходный комплект, сборка и замена библиотеки](../vendor/sources/heic/README.md) |
| WebP / JPEG XL | [Исходники и сборка современных кодеков](../vendor/sources/modern/README.md) |

Для gifenc нужны Node.js и esbuild. Для нативных библиотек используются
Emscripten, CMake и Ninja; точные версии и команды закреплены в соответствующих
исходных комплектах. Первичная установка инструментов выполняется отдельно.
Генераторы синтетических тестовых изображений используют Pillow/Pillow-Heif;
эти зависимости не входят в приложение.

Средство `relink.mjs` из комплекта HEIC заменяет кодек, уведомления и сведения
об исходном ZIP в копии обычного HTML. Исходный архив в HTML не встраивается.
При замене прежняя ссылка очищается, если не задан адрес изменённых исходников.
Порядок подготовки релизных ссылок остаётся в [PUBLISHING.md](PUBLISHING.md).

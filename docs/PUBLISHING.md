# Image Format Lab — выпуск приложения

Готовое приложение публикуется в [Releases](https://github.com/IlyaBarilo/image-format-lab/releases).
Пользователям предназначен image-format-lab.html. Постоянная ссылка:
[скачать последний выпуск](https://github.com/IlyaBarilo/image-format-lab/releases/latest/download/image-format-lab.html).

## Подготовка

Исходники приложения находятся в src/, зависимости сборки — в scripts/,
библиотеки и соответствующие исходники — в vendor/. В коммит включается
актуальный image-format-lab.html. [Сборка и проверки](DEVELOPMENT.md).
Рабочие материалы, журналы, установленные зависимости и результаты тестов
не включаются в репозиторий или релиз.

Перед выпуском:

1. Сохраните изменения в main и отправьте коммит.
2. Дождитесь успешного Checks для этого коммита.
3. Создайте и отправьте тег на проверенный коммит main.
4. Запустите Actions → Release → Run workflow из ветки main, указав этот тег.

Проверка отклоняет тег, коммит которого не входит в историю main.
Собираются исходники точного тега; более поздние изменения main не подменяют их.
Не переносите опубликованный тег на другой коммит.

## Номер версии

Поддерживаются стабильные числовые номера из одной–четырёх частей:
v1, v0.1, v0.1.0, v0.1.2.3. Полные SemVer-теги с суффиксами также допустимы,
например v1.2.3-rc.1. Префикс v необязателен; имя сохраняется дословно.

В релизном HTML номер отображается в окне **Лицензии**.
Обычная локальная сборка не показывает версию. Поля version в npm-манифесте
и реестре компонентов не задают номер выпуска приложения.

Пример создания тега в CMD из корня проекта:

```bat
git switch main
git status --short
git log -1 --oneline
git tag -a v0.1 -m "Выпуск Image Format Lab v0.1"
git push origin v0.1
```

Номер в примере заменяется выбранным номером выпуска. Тег должен указывать
на коммит с успешным Checks; незакоммиченные изменения в него не входят.

## Автоматическая публикация

Workflow Release собирает HTML с выбранным номером и ссылками на исходники,
выполняет полный набор тестов, проверяет состав и контрольные суммы вложений.
После успешных проверок выпуск публикуется автоматически.
Обычный push или отправка тега сами по себе релиз не создают.

В выпуск входят четыре файла:

| Файл | Назначение |
| --- | --- |
| image-format-lab.html | Автономное приложение |
| gifenc-1.0.3-sources.zip | Соответствующие исходники gifenc и лицензии |
| heic-sources.zip | Соответствующие исходники HEIC/AVIF, лицензии и средства пересборки |
| SHA256SUMS.txt | Контрольные суммы трёх файлов выше |

Стабильный выпуск получает Latest; предварительный — Prerelease.
Последний стабильный HTML доступен по постоянной ссылке без суффикса в имени.
При ошибке публикации сначала проверьте журнал и состояние выпуска:
повторный запуск не перезаписывает существующий релиз или черновик.
[Подробности workflow](CI.md).

## Ручная сборка по тегу

Сборка из выбранного checkout требует совпадения HEAD с тегом и наличия
истории main. Команды выполняются из корня проекта:

```bat
npm --prefix scripts run build:release -- --tag=v0.1 --repository=IlyaBarilo/image-format-lab
node scripts/build.mjs --release --tag=v0.1 --repository=IlyaBarilo/image-format-lab --check
```

Эти команды собирают и проверяют HTML; они не создают тег и не публикуют релиз.
Для проверки выпуска также нужны полный набор тестов и проверка скачивания
конкретных вложений. Workflow выполняет эти действия автоматически.

## Соответствующие исходники

Исходные ZIP предоставляются рядом с HTML с эквивалентным доступом без
дополнительной платы. Ссылки ведут к точному выпуску и доступны в окне
**Лицензии**; получателю не нужно скачивать ZIP для запуска приложения.
Постоянно меняющаяся ветка не заменяет соответствующие исходники выпуска.
[Условия и уведомления](../NOTICE.md).

Параметр --repository формирует адреса releases/download/тег/имя-файла.
Для другого сервера задайте два точных HTTPS-адреса в
[scripts/source-release.json](../scripts/source-release.json), поля urls.gifenc
и urls.heic. После изменения кодеков пересоздайте исходные ZIP, манифест
и HTML; для изменённых байтов используйте новый выпуск.

Средство relink.mjs из комплекта HEIC оставляет изменённый ZIP отдельно.
Его адрес задаётся через --source-url; без аргумента прежняя ссылка сбрасывается.
[Пересборка и замена](../vendor/sources/heic/README.md).

Для передачи на физическом носителе применяется подходящий способ
предоставления исходников по лицензиям компонентов. Необязательный упаковщик
scripts/package_offline.py собирает HTML, уведомления и два отдельных исходных ZIP.
Этот комплект не встраивается в приложение.

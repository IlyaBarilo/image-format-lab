# Image Format Lab — выпуск приложения

Готовое приложение публикуется в [Releases](https://github.com/IlyaBarilo/image-format-lab/releases).
Пользователям предназначен image-format-lab.html. Постоянная ссылка:
[скачать последний выпуск](https://github.com/IlyaBarilo/image-format-lab/releases/latest/download/image-format-lab.html).

## Подготовка

Исходники приложения находятся в src/, зависимости сборки — в scripts/,
библиотеки и соответствующие исходники — в vendor/. Готовый image-format-lab.html
не включается в коммит: его создаёт сборка в корне проекта, а пользователи
скачивают его из Releases. [Сборка и проверки](DEVELOPMENT.md).
Рабочие материалы, журналы, установленные зависимости и результаты тестов
не включаются в репозиторий или релиз.

1. Сохраните изменения в main и отправьте коммит.
2. Дождитесь успешного Checks для этого коммита. Проверки запускаются автоматически после push.
3. В Settings → General → Releases оставьте Enable release immutability выключенной:
   файлы приложения прикрепляются автоматизацией после публикации выпуска.

## Создание выпуска кнопкой

1. Откройте Releases → Draft a new release.
2. В Choose a tag введите номер, например v0.1, и выберите Create new tag.
3. В Target выберите main. До публикации убедитесь, что выбранная версия соответствует
   коммиту с успешным Checks. Если тег уже существует, используется его коммит.
4. Введите заголовок, например Image Format Lab v0.1, и описание выпуска.
5. Для последней стабильной версии выберите Set as latest release.
   Для предварительной версии используйте This is a pre-release.
6. Нажмите Publish release.

GitHub создаёт тег и выпуск. Событие публикации автоматически запускает
[Release](../.github/workflows/release.yml). Запускать Actions вручную и создавать
тег отдельной командой не требуется. Сохранение черновика кнопкой Save draft
не запускает сборку.

Обрабатываются только теги v*. Эта маска означает префикс v; дополнительно
проверяется числовой формат версии. Отдельное правило Rulesets для запуска
сборки не требуется. Публикация тега без префикса v пропускается автоматизацией;
неверный номер с префиксом v приводит к ошибке проверки.

## Номер версии

Поддерживаются стабильные номера из одной–четырёх числовых частей:
v1, v0.1, v0.1.0, v0.1.2.3. Полные SemVer-теги с суффиксами также допустимы,
например v1.2.3-rc.1. Имя сохраняется дословно, без добавления частей.

В релизном HTML номер отображается в окне **Лицензии**.
Обычная локальная сборка не показывает версию. Поля version в npm-манифесте
и реестре компонентов не задают номер выпуска приложения.

## Сборка и файлы

Автоматизация получает коммит события публикации и проверяет, что выбранный
тег по-прежнему указывает на него, а сам коммит входит в историю main.
Более поздние коммиты main не подменяют исходники выпуска. Не переносите
опубликованный тег на другой коммит.

Release собирает HTML с номером версии и ссылками на соответствующие исходники,
выполняет полный набор тестов, проверяет состав и контрольные суммы вложений.
Затем прикрепляет к уже созданному выпуску четыре файла:

| Файл | Назначение |
| --- | --- |
| image-format-lab.html | Автономное приложение |
| gifenc-1.0.3-sources.zip | Соответствующие исходники gifenc и лицензии |
| heic-sources.zip | Соответствующие исходники HEIC/AVIF, лицензии и средства пересборки |
| SHA256SUMS.txt | Контрольные суммы трёх файлов выше |

Сразу после Publish release этих вложений ещё нет: они появятся после сборки
и проверок. Перед распространением ссылки дождитесь зелёного Release и проверьте
скачивание HTML. Заголовок, описание, предварительный статус и выбор Latest
остаются заданными автором.

Последний стабильный HTML доступен по постоянной ссылке без суффикса в имени.
Для этого соответствующий выпуск должен быть отмечен Latest.
[Подробности автоматизации и обработки ошибок](CI.md).

## Если возникла ошибка

Выпуск уже опубликован, поэтому при неудачной сборке он остаётся без готовых
вложений либо с загруженной частью. Проверьте журнал Release перед распространением
ссылки. Автоматизация не удаляет выпуск, тег или файлы и не переписывает описание.

Повторный запуск может использовать уже прикреплённые файлы, только если их
размер и SHA-256 совпадают с проверенной сборкой. При конфликте одноимённых
файлов загрузка останавливается. Для изменённого кода или кодеков подготовьте
новую версию. Если неизменяемость релизов была включена, загрузка вложений
в опубликованный выпуск завершается ошибкой.

## Ручная сборка по тегу

Для отдельной проверки из выбранного checkout требуется совпадение HEAD с тегом
и наличие истории main. Команды выполняются из корня проекта:

```bat
npm --prefix scripts run build:release -- --tag=v0.1 --repository=IlyaBarilo/image-format-lab
node scripts/build.mjs --release --tag=v0.1 --repository=IlyaBarilo/image-format-lab --check
```

Эти команды собирают и проверяют HTML; они не создают тег и не публикуют релиз.
Обычный выпуск через кнопку Releases выполняет сборку и проверки автоматически.

## Соответствующие исходники

Исходные ZIP предоставляются рядом с HTML с эквивалентным доступом без
дополнительной платы. Ссылки ведут к точному выпуску и доступны в окне
**Лицензии**; получателю не нужно скачивать ZIP для запуска приложения.
Постоянно меняющаяся ветка не заменяет соответствующие исходники выпуска.
[Условия и уведомления](../NOTICE.md).

Параметр --repository формирует адреса releases/download/тег/имя-файла.
Для другого сервера задайте два точных HTTPS-адреса в
[scripts/source-release.json](../scripts/source-release.json), поля urls.gifenc
и urls.heic. После изменения кодеков пересоздайте исходные ZIP, манифест
и HTML; для изменённых байтов используйте новый выпуск.

Средство relink.mjs из комплекта HEIC оставляет изменённый ZIP отдельно.
Его адрес задаётся через --source-url; без аргумента прежняя ссылка сбрасывается.
[Пересборка и замена](../vendor/sources/heic/README.md).

Для передачи на физическом носителе применяется подходящий способ
предоставления исходников по лицензиям компонентов. Необязательный упаковщик
scripts/package_offline.py собирает HTML, уведомления и два отдельных исходных ZIP.
Этот комплект не встраивается в приложение.

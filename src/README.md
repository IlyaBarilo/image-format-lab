# Image Format Lab — исходники

Редактируйте файлы здесь, затем выполняйте `npm --prefix scripts run build` из корня проекта.
Готовый `image-format-lab.html` в корне создаётся автоматически и включает
стили, JavaScript, код Worker, сторонние библиотеки, лицензии и манифест.
Этот результат сборки не включается в Git; готовый HTML публикуется в Releases.
Для использования готового приложения скачивайте
[image-format-lab.html из последнего релиза](https://github.com/IlyaBarilo/image-format-lab/releases/latest/download/image-format-lab.html).
Постоянное имя релизного файла совпадает с именем результата локальной сборки.
Корневые `LICENSE`, `NOTICE.md` и `ASSETS.md` входят в `embedded-notices`;
watch отслеживает их изменения. Туда же включены лицензии esbuild и Acorn.
Сборщик приводит окончания строк непосредственно включаемых текстов проекта
(шаблон, CSS, SVG, `embedded-notices`) к LF, чтобы настройки Git и редактора не меняли HTML.
Файлы `vendor/` и их лицензии сохраняют закреплённые байты без преобразования.
В gzip-заголовках сжатых модулей используется OS=255, без метки системы сборки.
Лицензии библиотек, `vendor/components.json`, манифест и `sourcePackages`
(имя, размер, SHA-256, адрес каждого исходного ZIP) входят в `embedded-codecs`.
Читаемые исходники gifenc и ZIP HEIC/AVIF остаются в `vendor/` отдельно от HTML.
Окно `ui/licenses.mjs` показывает тексты, создаёт TXT локально и даёт ссылки
на отдельные ZIP. Сеть используется только при явном переходе по ссылке.
Пустые адреса в [source-release.json](../scripts/source-release.json) означают
ненастроенные ссылки. Для GitHub релизная команда формирует оба адреса
по параметру `--repository=IlyaBarilo/image-format-lab`; без него используются
адреса из JSON и они должны быть заполнены.
Сборщик проверяет целостность обоих ZIP и соответствие исходным файлам,
но не проверяет наличие файлов на удалённом сервере.
Для открытия готового файла не нужны `src/`, `vendor/`, Node.js или сервер.

Обычная команда `npm --prefix scripts run build` создаёт локальный HTML **без отображения версии**.
Для релиза используется `npm --prefix scripts run build:release -- --tag=v1.2.3 --repository=IlyaBarilo/image-format-lab`, где пример
заменяется выбранным существующим тегом. CLI проверяет совпадение тега и HEAD;
тег дословно отображается у Image Format Lab в окне «Лицензии».
В `embedded-codecs.releaseTag` хранится тег или `null` для локальной сборки.
Версии библиотек остаются в реестре компонентов; `scripts/package.json.version` и
поле версии приложения в реестре не задают номер пользовательского выпуска.
`scripts/build-version.mjs` проверяет формат тега и checkout. Сборочный API
`buildViewer({release: true, tag, sourceConfig})` формирует HTML в памяти для
тестов без Git; для выпуска используется CLI с проверкой checkout.
[Полная инструкция](../docs/PUBLISHING.md) и [GitHub Actions](../docs/CI.md).

Три крупных исполняемых модуля — HEIC/AVIF, JPEG и JPEG XL/WebP — хранятся в
`scripts` как `{encoding: "gzip-base64", bytes, data}`. Остальные четыре скрипта
остаются строками. `bytes` и хеш манифеста относятся к распакованному оригиналу.
Сервис кодеков дожидается встроенной pako перед запуском этих Worker; общий
`loadScript` объединяет одновременные запросы. `core/codec-payload.mjs`
восстанавливает точный UTF-8, проверяет gzip и размер. `embedded-codecs.mjs`
сохраняет успешно распакованный текст: последующие Worker повторно его используют.
При ошибке частичный результат не сохраняется; доступен повтор запуска.
Лицензии, уведомления и полный манифест не сжимаются, JS/CSS не минифицируются.
Сборочный API `buildViewer({compressCodecs: false})` предназначен для сравнения
с обычным хранением в памяти; штатная команда собирает сжатый HTML в корне.
`relink.mjs` сохраняет способ хранения заменяемого кодека и работает также
с прежним HTML, где кодек был обычной строкой.

## Связи между частями

Чистые вычисления импортируются обычными `import`/`export`. Они не обращаются
к `app` или `els`; исходник передаётся аргументом. GIF/BMP и метрики используются
и основной страницей, и Worker из одних модулей.

Компоненты интерфейса и сервисы создаются функциями `create…`. Состояние и элементы
DOM передаются через первый аргумент. Второй аргумент `deps` содержит только
перечисленные в `application.mjs` операции. Все компоненты создаются перед `init()`;
связи читаются при выполнении операций. Это позволяет компонентам взаимодействовать
без циклических импортов и управляемо имитировать сбои в тестах.

При добавлении зависимости включите её в список соответствующего компонента
в `application.mjs`. Состояние UI общее; взаимодействия между компонентами передаются через
зависимости, предоставленные application.mjs.

Настройки сравнения и пакета разделены. Пакет обрабатывает явный исходник
и снимок параметров; переключать выбранный файл для обработки нельзя.
Счётчики поколений, проверка актуальности и освобождение ресурсов сохраняются
при изменении интерфейсных компонентов.

## Представление пикселей

`core/pixel-buffer.mjs` описывает плотно упакованный RGBA-растр: `width`, `height`,
`data`, `sampleType` (`uint8`, `uint16`, `float32`), `bitDepth`, `colorSpace`,
`alphaMode` и вычисленный `byteLength`. Разрядность относится к рабочим отсчётам,
а не к исходному файлу. Для целых чисел хранятся исходные уровни (например 0–1023
при 10 битах в Uint16Array); float32 не ограничивается диапазоном 0–1.

`createPixelBuffer` проверяет тип, геометрию, длину и необязательный лимит `maxBytes`,
не сканируя значения пикселей. `pixelBufferByteLength` рассчитывает объём без выделения
памяти. Число байтов относится к рабочему представлению массива, не к общей памяти
процесса. Описатель неизменяем, но сам массив остаётся изменяемым и принадлежит вызывающему
коду: оборачивание не копирует и не передаёт буфер. `clonePixelBuffer` явно создаёт
независимую побайтовую копию, включая только используемый участок массива.

`colorSpace` принимает `srgb`, `display-p3` или `unknown`; `alphaMode` — `straight`
или `premultiplied`. Неизвестное пространство нельзя считать sRGB без основания.
Это описание данных; модуль не выполняет преобразование цвета, HDR или проверку
значений каждого канала на соответствие заявленной разрядности.

`core/pixels.mjs` связывает описание с нынешним RGBA8 ImageData. Адаптеры используют
тот же массив; `cloneImageData` создаёт независимую копию с сохранением цветовой метки.
Вход с высокой разрядностью или premultiplied alpha нельзя молча привести к RGBA8.
Цветовая метка ImageData описывает рабочие пиксели, а не доказывает наличие или
сохранность цветового профиля исходного файла.

`services/decode.mjs` возвращает `pixelBuffer` рядом с `imageData` у исходника и
декодированного результата. `services/encode.mjs` обновляет его при уменьшении и ICO,
а `sourcePixelBuffer` результата кодирования описывает эталон для этого результата.
Ячейка сравнения хранит описатель вместе с пикселями и освобождает обе ссылки.
Пакетный предпросмотр сохраняет только bitmap; новый описатель не удерживает
дополнительный массив после измерений. PNG16 и поддерживаемый TIFF16 читают
и сохраняют uint16 отдельно от предпросмотра; прочие кодеки и пространственные
графики пока работают в RGBA8.
`core/display-sdr.mjs` отображает целочисленные RGBA8/16 с общими для окон
чёрной/белой точками, экспозицией и упорядоченным дизерингом 16→8 бит.
`ui/display.mjs` готовит временный Canvas по строкам и ограничивает его 12 Мп;
`ui/canvas.mjs` использует его только при рисовании. Точные буферы,
измерения и кодирование от настроек экрана не зависят.
При запуске `ui/display.mjs` проверяет реальный `colorType: float16` контекста и
`rgba-float16` для `ImageData`; при успехе окна просмотра запрашивают float16
контексты и сверяют их фактические атрибуты. Для 16-битных целых отсчётов
временный Canvas использует нормированные
float16-значения. Отказ создания/записи возвращает экранный RGBA8-путь.
Это внутренняя точность Canvas, не проверка физического вывода монитора;
точные Uint16-буферы остаются отдельно.
Модель, числовые метрики и гистограмма поддерживают uint16/float32. Наличие float32
в вычислительном API само по себе не добавляет чтение HDR-файлов.

## Числовые метрики

`core/metrics.mjs` предоставляет `computePixelMetrics(a, b, options)`: оба аргумента —
описатели pixelBuffer, результат — `{ psnr, alpha }`. PSNR сравнивает все каналы RGB
на белой подложке в пространстве кодовых значений. `alpha` — средняя абсолютная
разность прозрачности в процентах. Цветовое преобразование, линейная обработка света
и приведение размеров не выполняются.

Для целых отсчётов полный уровень равен `2 ** bitDepth - 1`. Разные разрядности
сопоставляются по нормированной шкале: например, значение uint8, умноженное на 257,
эквивалентно ему в uint16 при одинаковых цветовых метках и правилах alpha.
Для float32 обязателен явный `floatPeak`: положительный опорный RGB-уровень белого
и пик PSNR в диапазоне от минимального положительного до максимального конечного
числа float32. Он применяется к обоим float32-аргументам; их alpha всегда в 0–1.
Конечные RGB могут выходить за пределы 0–floatPeak, без обрезания. Это числовая
метрика с заданной шкалой, а не поддержка HDR или абсолютной яркости.

`straight` alpha учитывается при сравнении; `premultiplied` уже содержит умножение
RGB на alpha в том же пространстве кодовых значений. Размеры должны совпадать.
Разные известные цветовые пространства отклоняются. Неизвестная метка требует
явного `allowUnknownColorSpace: true`; это разрешает сравнить кодовые значения,
но не подтверждает соответствие цветов. Нынешние RGBA8-потребители включают эту
политику для ImageData старых браузеров без цветовой метки; разные известные метки
даже с ней не сравниваются. Отсчёты вне заявленной целой разрядности, NaN/Infinity
и float-alpha вне 0–1 отклоняются, включая RGB под полностью прозрачным пикселем.

`prepareMetricInputs` проверяет описатели и параметры без копирования/сканирования
массива, фиксирует параметры операции. Проверка значений выполняется при расчёте.
`services/compute.mjs` передаёт описатели и параметры в Worker, если суммарный объём
двух рабочих массивов составляет не менее 8 000 000 байт; этот порог сохраняет прежнее
поведение для RGBA8. Исходные массивы не отсоединяются; `postMessage` создаёт рабочие
копии. Без Worker используется тот же алгоритм в основном потоке.

Сравнение и пакетный предпросмотр передают `sourcePixelBuffer` и `pixelBuffer`
декодированного результата. Ошибка расчёта освобождает ещё не опубликованный bitmap.
Прежние функции `computePsnr`/`computeAlphaError` для массивов остаются совместимыми
с RGBA8; для других типов предназначена только `computePixelMetrics` с описателями.
Арифметика прежних измерений RGBA8 сохранена.

## Гистограмма

`computeHistogram(pixelBuffer, matte, region, options)` получает точные пиксели,
без преобразования через Canvas. Вход ImageData RGBA8 сохранён для совместимости.
Целые каналы имеют `2 ** bitDepth` счётчиков Uint32: до 65 536 уровней,
без предварительного усечения до 8 бит. RGB смешивается с белой или чёрной подложкой
в пространстве кодовых значений и округляется до ближайшего целого уровня.
Альфа учитывается отдельно. Premultiplied означает умножение в том же пространстве.
Прежние подсчёты и округление RGBA8 сохранены.

Для float32 нужны явные `options = { range: [min, max], bins, floatPeak }`.
Число интервалов — 2–65 536; они равномерные, левая граница включена, правая
исключена, кроме последнего интервала, включающего максимум. `floatPeak` задаёт
белую подложку; диапазон RGB может включать отрицательные значения. Для alpha
диапазон всегда 0–1 с тем же числом интервалов. NaN/Infinity, неверная alpha и целые
отсчёты вне действующей разрядности отклоняются. Проверяются пиксели выбранной
области. Размер ограничен 40 Мп, исходные массивы не изменяются и не копируются.

Результат содержит `scale`, тип/разрядность, цветовую метку, режим alpha,
`channels`, `underflow`, `overflow` и `means`. Выход за диапазон не переносится
в крайние интервалы. Для каждого канала сумма счётчиков с выходами равна числу
пикселей области. Средние включают значения вне диапазона; для целых используются
округлённые уровни, для float — значения до разбиения на интервалы.

`core/histogram-view.mjs` согласует шкалы и группирует данные для показа, сохраняя
исходные массивы. Известные разные цветовые пространства и разные RGB-подложки
несовместимы. Неизвестная метка требует `allowUnknownColorSpace: true`; текущий
интерфейс явно использует эту политику, как при расчёте метрик. Разные целые
разрядности нормируются к 0–1: каждый уровень отображается на ближайший уровень
наиболее подробной целой сетки. Float сравнивается только с float при одинаковых
диапазоне, числе интервалов и белом. Цветовых преобразований нет.

Для ширины графика соседние счётчики суммируются; сетка общая для сравниваемых
ячеек. Обычная 256-уровневая кривая не сокращается. «Разница» вычитает доли
в процентных пунктах, включая отдельные разницы ниже/выше диапазона; внутри
экранной группы противоположные отличия могут компенсироваться. В JSON остаются
все исходные счётчики, шкалы и точная сетка разницы. PNG повторно группирует данные
под собственную ширину, независимо от размера панели.

Анализ получает `variant.pixelBuffer`; для float32 параметры расчёта передаются
через `variant.histogramOptions`. Они фиксируются для запроса и входят в ключ кеша.
Worker получает описатель без transfer list, поэтому исходные буферы не отсоединяются.
Поле `settings.level` и сохранённая настройка остаются позицией указателя 0–255;
подпись показывает соответствующий уровень/интервал шкалы. Это не параметр
разрядности файла. Чтение/запись PNG16 выполняет отдельный PNG-модуль; полноценный HDR не предоставляется.

## Сборка

Команды ниже выполняются из корня проекта. Npm-манифесты находятся в
`scripts/package.json` и `scripts/package-lock.json`; зависимости —
в `scripts/node_modules/`. Корневой HTML собирается по пути относительно
самого сборщика, независимо от текущего рабочего каталога.

- `npm ci --prefix scripts` — установить зафиксированные зависимости разработки.
- `npm --prefix scripts run build` — обновить HTML в корне. После успешной сборки временный результат
  заменяет прежний файл; ошибка подготовки не перезаписывает прежний HTML.
- `npm --prefix scripts run dev` — автоматически пересобирать HTML при изменении явно известных
  исходников и зависимостей. После изменения самого сборочного скрипта перезапустите
  команду. Наблюдение не обходит проект или пользовательский `local/`.
- `npm --prefix scripts run build -- --check` — проверить, что HTML соответствует исходникам.
- `npm --prefix scripts run build -- --debug` — включить встроенную карту исходников для отладки.
  Перед распространением снова выполните обычную сборку.
- `npm --prefix scripts run test:build` — проверить воспроизводимость, встраивание, импорты и граф модулей.

`scripts/build.mjs` сначала собирает отдельную точку входа Worker, затем встраивает
её текст через виртуальный импорт `viewer:compute-worker`. Вычислительный Worker использует тот же граф импортов, что и основные модули.

Сторонние библиотеки читаются из фиксированного списка `vendor/`, проверяются
по SHA-256 и включаются как данные. `init()` автоматически запускает встроенные
кодеки через Blob; pako как общая зависимость выполняется один раз. Общий запрос
активации и запросы отдельных библиотек объединяют повторные вызовы.
При успехе, ошибке и тайм-ауте временная ссылка скрипта освобождается.
Рядом со статусом только при ошибке появляется повтор; готовые библиотеки
заново не запускаются. Внешнего сетевого или файлового запасного пути нет.
Для обновления библиотек отдельно проверяйте версии, лицензии и
`scripts/build-vendor.cjs` / `vendor/manifest.json`.

`scripts/vendor-files.cjs` задаёт общий явный список кодеков, уведомлений
и исходного комплекта. `node scripts/build-vendor.cjs` пересобирает gifenc
из `vendor/sources/gifenc-1.0.3/src/`, обновляет обёртку, копии лицензий
в исходном комплекте и хеши манифеста. После изменения этих исходников,
лицензий или реестра сначала выполните эту команду, затем `npm --prefix scripts run build`.
Она использует установленный esbuild и ничего не скачивает. Изменения
сборочных скриптов требуют перезапуска watch.

HEIC: `services/heic.mjs` управляет отдельным Worker, собираемым из
`workers/heic.worker.mjs`. Фабрика `vendor/heic-decoder.js` встроена в Blob.
Worker возвращает RGBA8 и завершается после каждого изображения/ошибки.
`vendor/sources/heic/README.md` описывает сборку C/C++, сохранение изменённых
исходников и замену декодера. Обычный `npm --prefix scripts run build` компилятор не запускает.

TIFF: `services/tiff.mjs` последовательно запускает операции в отдельном Worker.
В него входят libnsbmp, libtiff, адаптированный UTIF, pako и `jpeg-decoder.js`; после каждого файла
Worker завершается и освобождает WASM-память. Предварительно проверяются каталоги,
диапазоны данных и размер изображения. `core/tiff-jpeg.mjs` собирает JPEG-потоки
из TIFF-таблиц/полос и сохраняет значения 8/12/14/16 бит. Исходники и сборка
libjpeg-turbo описаны в [инструкции](../vendor/sources/jpeg/README.md).
Его исходный архив проверяется сборщиком по манифесту, но не встраивается в HTML;
декодер и применимые уведомления встраиваются полностью.
При изменениях комплекта сначала выполните `python vendor/sources/heic/package.py
--output vendor/heic-sources.zip` (одной строкой), затем `node scripts/build-vendor.cjs`
и `npm --prefix scripts run build`. Сборщик сверяет не только SHA-256 ZIP, но и каждый его файл
с явным списком исходного комплекта, поэтому устаревший ZIP не пройдёт сборку.

## Проверки

Полный запуск описан в `tests/README.md`. Проверки алгоритмов импортируют настоящие
модули. Сценарии гонок используют временную сборку с адаптером
`tests/support/browser-entry.mjs`, который даёт тестам доступ к состоянию
и подменяемым операциям. Он не включается в обычный HTML.

`tests/standalone-release.cjs` отдельно открывает копию **обычного корневого HTML**
во временной папке с отключённой сетью и проверяет работу через интерфейс
и настоящие скачивания. Проверка инструментированной сборки не заменяет этот тест.

## AVIF / JPEG XL / JPEG 2000 / WebP lossless / TIFF / ICO

`services/heic.mjs` и HEIC Worker обслуживают также AVIF (libaom).
`core/avif-options.mjs` проверяет скорость AVIF 0–9 с прежним значением 6;
параметр передаётся только в AVIF-кодировщик через HEIC Worker. Путь HEIC не меняется.
`services/modern.mjs` / `workers/modern.worker.mjs` обслуживают JPEG XL и WebP lossless;
[сборка из исходников](../vendor/sources/modern/README.md).
Отдельные операции `jpeg-to-jxl` и `jxl-to-jpeg` передают исходный файл через
тот же Worker в libjxl без декодирования в RGBA. Они не входят в форматы ячеек:
`ui/study.mjs` предлагает их в «Экспериментах» и перед скачиванием JXL
побайтово сравнивает исходный JPEG с восстановленным. Вход ограничен 64 МиБ,
выход нативного моста — 256 МиБ; JXL без reconstruction metadata отвергается.
`core/modern-options.mjs` проверяет WebP method 0–6 и JPEG XL effort 1–10
с прежними значениями 4 и 5; параметры доходят до пересобранного C++-моста.
Обычный WebP использует браузерный кодировщик, поэтому его метод недоступен.
`services/jpeg2000.mjs` запускает отдельный одноразовый Worker для каждого
изображения и загружает встроенный OpenJPEG. Он читает и пишет контейнер JP2 и
кодовый поток J2K Part 1. Мост `vendor/sources/jpeg2000/bridge.c` принимает
целые 8/16-битные Gray/RGB/RGBA без субдискретизации. Выходной 16-битный
`PixelBuffer` остаётся отдельным от 8-битного предпросмотра и участвует в
точных измерениях. Качество 100 выбирает обратимое кодирование, меньшие значения
задают целевой коэффициент сжатия. Работают пределы 64 МиБ входа, 8/4 Мп
растра и 1 МиБ ICC. Поддерживаемый матричный RGB ICC создаёт отдельный
SDR-растр sRGB для просмотра и анализа; исходные коды и профиль передаются
в запись JP2 без изменения размера. Путь J2K кодирует sRGB-копию и не переносит
ICC. [Исходники и сборка](../vendor/sources/jpeg2000/README.md).
TIFF Worker использует
`core/raster-codecs.mjs` и libtiff с zlib: без сжатия, Deflate или LZW;
PackBits записывается собственным кодировщиком RGBA8 в том же модуле.
`core/tiff16.mjs` читает ограниченный набор целых TIFF16 без понижения разрядности:
смежные серые/RGB/RGBA-каналы, независимый alpha, ориентация 1, полосы без
сжатия, Deflate или PackBits. Запись RGBA16 поддерживает отсутствие сжатия и
Deflate. Неподдерживаемый точным путём TIFF16 передаётся прежнему 8-битному
декодеру с явной пометкой потери точности; это сохраняет чтение JPEG-in-TIFF16.
Worker передаёт точный Uint16Array отдельно от 8-битного ImageData для Canvas;
инспектор, гистограмма и метрики получают точный буфер. Другие пространственные
графики пока работают по предпросмотру. Лимит точного TIFF16 — 12 Мп.
RGB ICC из тега 34675 классического TIFF проверяется в основном потоке и создаёт
отдельную sRGB-копию; исходные отсчёты и профиль могут быть повторно записаны в
TIFF16 без изменения размера. Профиль неподдерживаемой точным путём страницы
не передаётся молча в 8-битный декодер. BigTIFF16 с ICC отклоняется.
`core/tiff-encode.mjs` сохраняется как независимая реализация для тестов. `core/ico.mjs` записывает контейнер PNG
и безопасно выбирает наибольший встроенный PNG при чтении. Все операции используют
явный исходник и общую очередь кодирования; пиксели исходника не передаются с потерей владения.

Параметры TIFF `tiffDepth`, `tiffCompression`, `tiffLevel`, `tiffPredictor` проверяются
в `core/raster-codecs.mjs`. `ui/controls.mjs` показывает параметры прямо над
изображением; `ui/format-settings.mjs` открывает их для черновика пакета.
Настройки варианта и черновика пакета
не смешиваются. Параметры входят в профили, localStorage и CSV/JSON-отчёты.

## Точный PNG

`core/png.mjs` также записывает статический индексированный PNG: общие
с GIF палитра и индексы строятся в `core/gif.mjs`, затем строки упаковываются
по 1/2/4/8 бит, записываются PLTE и при необходимости tRNS, после чего
встроенный pako сжимает IDAT. Для честного сравнения при одинаковых
настройках собственный GIF получает те же цвета и индексы. Результат
проверяется независимым декодером; паспорт результата показывает число
записанных и использованных записей палитры. Формат использует RGBA8
и ограничен 12 Мп. Новая внешняя библиотека не нужна.

`core/png.mjs` реализует статические PNG по [спецификации PNG](https://www.w3.org/TR/png-3/):
контейнер, CRC, все фильтры, Adam7, прозрачность tRNS и независимые каналы.
Распаковка встроенным pako имеет заранее рассчитанный предел и ограниченные
чанки, до крупных выделений проверяются геометрия и цветовые блоки.
`services/png.mjs` загружает существующий pako и разделяет точный PixelBuffer
и округлённый ImageData для экрана. PNG16 определяется по сигнатуре, независимо
от расширения/MIME; PNG8 без ICC по умолчанию оставляет браузерный путь,
а RGB/RGBA PNG8 с ICC читает собственный декодер. При явном выборе фильтра
PNG8 записывается собственным кодировщиком. Повторное чтение своего
результата использует явный флаг `exactPng`.

В интерфейсе полноцветный PNG, палитровый PNG и PNG opt объединены: выбор
режима переводится в прежние внутренние `png` / `pngIndexed` / `pngUpng`
для совместимости профилей.
В отчёте формат и режим выводятся раздельно; протокол сохраняет внутренние
настройки для воспроизведения. `pngDepth` — строка `auto`, `8` или `16`; `pngFilter` выбирает стандартный,
адаптивный либо один из пяти фильтров PNG, `pngLevel` задаёт Deflate 1–9.
Настройки входят в профили,
localStorage и отчёты. Без ICC PNG16 и явное понижение PNG16→PNG8 используют
точные пиксели, не чтение обратно из Canvas. При поддерживаемом ICC полноцветный
PNG8/PNG16 без изменения размера получает исходные коды и профиль; при уменьшении
остаётся sRGB-копия. PNG16 с уменьшением отклоняется.
Без ICC 16-битные коды передаются в метрики и гистограмму, включая вариант
«Исходный файл». С матричным RGB ICC `core/icc-sdr.mjs` строит sRGB-копию
той же целой разрядности для просмотра и анализа; оригинальные коды остаются
в `nativePixelBuffer`. Кривые `curv`/`para`, матрица RGB→XYZ D50 и переход в
sRGB реализованы собственным кодом; LUT-, CMYK- и HDR-профили отклоняются.
Остальные операции используют RGBA8 с пояснением в интерфейсе.
Предел точного пути — 12 Мп / 128 МиБ, ICC — 1 МиБ. PNG-код работает в основном потоке;
метрики и гистограмма используют существующий вычислительный Worker.
При записи полноцветного PNG8/PNG16 в исходном размере `iCCP` и исходные коды
сохраняются с округлением при смене разрядности; уменьшение и форматы без переноса
ICC используют sRGB-копию. EXIF не копируется.
Новые сторонние компоненты не требуются.

## Инспектор пикселя

`samplePixel` валидирует описатель и выбранные четыре отсчёта, не сканирует и не
копирует весь растр. `comparePixelSamples` сравнивает кодовые значения той же
координаты при совпадающих размерах и совместимых цветовых/alpha-метках.
Целые разрядности приводятся к общей шкале только для вычисления разницы;
исходные числа в таблице остаются нативными. Неизвестное пространство допускает
сравнение кодов с пояснением, float32 требует отдельного диапазона для разницы.

Контроллер хранит точку и незавершённый жест в сеансе. Источник и его поколение
сбрасывают выбор, `isVariantReady` исключает старые результаты. `updateMetrics`
обновляет числа при инвалидировании и готовности ячейки. `canvas.mjs` передаёт
события указателя и рисует маркер после изображения; `redrawPreviews` не вызывает
анализ или кодирование. Отмена, смена данных во время жеста, второй указатель,
колесо и движение более четырёх CSS-пикселей отменяют выбор точки. Геометрия
учитывает отдельные коэффициенты CSS/backing-buffer по X и Y.

## Паспорт файла

`inspectFile` читает фактический File/Blob через окно до 64 КиБ; суммарный предел
чтения — 64 МиБ, число структурных блоков/маркеров — до 10 000. PNG пропускает
сжатые IDAT, JPEG просматривает энтропийные участки порциями, учитывает FF00,
RST, несколько сканов и метаданные между ними. Проверяются длины, границы,
ключевые поля и CRC IHDR; это не декодер и не полная валидация файла.
Тот же проход строит непрерывную карту диапазонов байтов: сигнатуру и чанки PNG,
маркеры и данные сканов JPEG, хвост после EOI. В интерфейс передаётся не более
1024 строк; счётчики скрытых участков и покрытых байтов сохраняются. IDAT
не загружается целиком ради карты. Ошибка или лимит чтения помечают её неполной.
При частичном разборе отсутствие метаданных остаётся неизвестным.
ICC, EXIF и XMP определяются по распознанным заголовкам без чтения их содержимого
как профиля/дерева/XML. Полный размер файла и размеры из SOF/IHDR задают bpp.

Чтение происходит при открытии окна через подпись «Формат ⓘ». Контроллер
передаёт AbortSignal и проверяет исходник, поколение, Blob и выбранную ячейку
после завершения. Готовые паспорта кешируются в WeakMap по Blob; закрытие окна,
смена выбора или инвалидирование результата отменяет текущий запрос.
`workingRasterInfo` возвращает только описание и byteLength, без копирования
или сканирования пикселей. Цветовая схема JPEG по маркерам не является
утверждением о цветовом пространстве ICC или рабочего растра.

Форматы заголовков: [PNG](https://www.w3.org/TR/png-3/),
[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf),
[JFIF](https://www.w3.org/Graphics/JPEG/jfif3.pdf).
Реализация собственная; новых сторонних компонентов нет.

`core/processing-timing.mjs` разбивает время готового варианта по монотонным
границам. `services/encode.mjs` отмечает начало и конец фактической работы в
последовательной очереди; `ui/comparison.mjs` отмечает обратное чтение и метрики.
Ожидание очереди отдельно попадает в интервал до кодирования. Остаток между
измеренными стадиями записывается в «Прочее». Стадии хранятся в measurement,
показываются в паспорте результата и входят в JSON/CSV; исходник их не получает.
Существующее округлённое `processingMs` сохраняется.
